# Emacs 31.1 compatibility review

Reviewed `early-init.el` and `init.el` (excluding `elpa/`, `tree-sitter/`, `var/`)
against the official Emacs 31.1 NEWS and ORG-NEWS (`emacs-mirror/emacs`, tag
`emacs-31.1`).

## Real incompatibility

- [ ] **`c-ts-mode-indent-offset` and `go-ts-mode-indent-offset` were renamed.**
  NEWS ("Incompatible Lisp Changes in Emacs 31.1"):

  > `'FOO-ts-mode-indent-offset'` renamed to `'FOO-ts-indent-offset'` ...
  > `'go-ts-indent-offset'`, ... `'c-ts-indent-offset'`.

  Affected:
  - `init.el:1016` — `(c-ts-mode-indent-offset 4)` inside `use-package c-ts-mode`
  - `init.el:1022` — `(go-ts-mode-indent-offset 4)` inside `use-package go-ts-mode`

  This is listed under *incompatible* changes (no obsolete alias kept), so on
  31.1 these `:custom` settings silently set unused variables and the
  indent-offset customization stops taking effect (mode falls back to its
  default).

  Fix: rename to `c-ts-indent-offset` and `go-ts-indent-offset`.

## Minor/cosmetic notes (not breaking)

- [ ] `init.el:162` — `(when-let ((parent (file-name-directory filename))) ...)`
  uses the single-binding-list form of `when-let`, now obsolete (`if-let`/
  `when-let` → use `when-let*`). Still works; only produces an obsolescence
  warning, which is already suppressed by `warning-minimum-level :error` and
  `native-comp-async-report-warnings-errors nil`.
- [ ] `init.el:80-82` — the `mode-line-format` deletion of the `vc-mode`
  segment still works, but Emacs 31 changed the *default*
  `mode-line-format`/`mode-line-position` to no longer specify minimum
  widths. Purely cosmetic; only matters if using a proportional-width
  mode-line font.

## Checked, no issues found

Nothing else in the config touches any of the other removed/renamed items in
31.1: unexec dumper, old `ctags`, hashcash, `display-comint-buffer-action`,
`php-ts-mode-css-fontify-colors`, `cl-*` renames, Org 9.8 changes
(`org-adapt-indentation` default change doesn't apply — it's explicitly set),
etc. None of those names/variables appear in `early-init.el` or `init.el`.

## New 31.1 features that would strictly improve this config

(Vertico/Corfu/Consult/etc. are out of scope here — not suggesting a switch
to native completion.)

- [ ] **Replace `r/remap-to-treesitter-modes` with the new
  `treesit-enabled-modes`.** (`init.el:662-675`)
  NEWS: *"New user option `treesit-enabled-modes`. You can customize it
  either to `t` to enable all available tree-sitter-based modes, or to
  select a list ... Depending on your customization, it modifies the
  variable `major-mode-remap-alist` from the corresponding variable
  `treesit-major-mode-remap-alist` prepared by tree-sitter-based mode
  packages."* Setting `(treesit-enabled-modes t)` (plus optionally
  `treesit-auto-install-grammar`) replaces the hand-maintained
  `major-mode-remap-alist` list with a built-in mechanism that also picks
  up new bundled ts-modes (e.g. `mhtml-ts-mode`, `go-work-ts-mode`)
  automatically. `php-ts-mode` (third-party) would still need its own
  `:mode` entry since it isn't part of this core list.

- [ ] **Add `show-paren-not-in-comments-or-strings` to the `show-paren`
  settings.** (`init.el:102-104`) New option that tells `show-paren-mode`
  not to highlight parens inside comments/strings (values: `t`, `'all`,
  `'on-mismatch`). Also note: *"Tree-sitter enabled modes now properly
  support `show-paren-mode`"*, so this now works correctly in your
  `*-ts-mode` buffers too.

- [ ] **Add `dired-hide-details-hide-absolute-location`.** (`init.el:199-210`,
  where `dired-hide-details-mode` is already hooked on) New option to also
  hide the absolute `default-directory` line in Dired when details are
  hidden, e.g. showing `project:` instead of
  `/absolute/path/to/project:`. Fits the already-minimal Dired setup
  (`diredfl`, `dired-subtree`, hidden details).

- [ ] **Enable `kill-region-dwim`.** New option: when non-nil, `C-w`
  (`kill-region`) with no active region kills the last word instead of
  signaling an error. Complements the existing `r/kill-whole-word`
  helper (`init.el:331-334`, bound to `C-M-d`) and removes a common
  papercut without changing any existing binding.

- [ ] **Set `native-comp-async-on-battery-power` to `nil`.** New option
  to skip starting async native-compilation jobs while on battery power.
  Given the touchpad-specific bindings already in the config
  (`init.el:53-56`), this machine is likely a laptop, so this is a free
  battery-life win alongside the existing `gcmh` tuning.

- [ ] **Add `save-place-autosave-interval` (e.g. `300`).** (`save-place-mode`
  is hooked in `init.el:33`) New option to periodically auto-save point
  positions instead of only on clean shutdown, so `save-place` survives a
  crash or `kill -9`. Must be set with `setopt`, not `setq`/`:custom`
  plain `setq` — check `use-package`'s `:custom` still applies it via
  `customize-set-variable`, which is fine here.

- [ ] **Add `(flymake-show-diagnostics-at-end-of-line 'fancy)`.**
  (`init.el:654-660`) New `'fancy` value lays out diagnostics below the
  affected line using Unicode connectors, in the same spirit as the
  already-enabled `eldoc-box` and `breadcrumb` UX touches.

- [ ] **Consider the new built-in Tramp sudo commands as a complement to
  `r/sudo-find-file`.** (`init.el:265-282`, `316`) 31.1 adds
  `tramp-dired-find-file-with-sudo` (bound to `@` in Dired) and binds
  `C-x x @` to `tramp-revert-buffer-with-sudo` — the latter covers a case
  your custom `r/sudo` helper doesn't (re-opening an *already-visited*
  file as root in place). Not a replacement, just a gap-filler worth
  knowing about.

- [ ] **Consider `recentf-exclude-ignored-extensions`.** (`init.el:139-155`)
  New predicate-based option that can subsume some of the manually
  maintained extension regexps (`\.gif$`, `\.jpe?g$`, `\.m4v$`, `\.mp4$`,
  `\.pdf$`, `\.png$`, `\.webp$`) in `recentf-exclude`, if those extensions
  are added to `recentf-exclude-ignored-extensions` (default source is
  `completion-ignored-extensions`, which doesn't include them by
  default, so this only pays off if you're open to maintaining that list
  instead of the regexps).
